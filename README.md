# ナディーショーダナ（片鼻呼吸法）

ナディーショーダナを視覚的にガイドする PWA です。スマホのホーム画面に追加すると、オフラインでも単体アプリとして起動します。

## 画面の読み方

セッション画面は 3 本のバーが ∩ 字に並びます。

- **左右の縦バー** … 吸う / 吐く。常に上端を固定して高さが増減します。**減る＝吸う、増える＝吐く**
- **上辺の横バー** … 止める。息が入ってきた側から減っていきます

1 ラウンドは 6 フェーズです。

1. 左から吸う
2. 止める（両鼻）
3. 右から吐く
4. 右から吸う
5. 止める（両鼻）
6. 左から吐く

バーの分割数は秒数と一致します（止める 8 秒なら 8 分割）。色の境界はマス内を連続的に動き、1 秒ごとに目盛り線を通過します。

目盛りが出ないのは次の 2 つの場合だけです。どちらも意図した動作です。

- **1 秒のフェーズ** … 区切る位置が無いため、目盛りなしの連続バーになります
- **1 マスが細かくなりすぎる場合** … カスタムで極端に長い秒数を指定したときなど。線が潰れて読めなくなるより、連続バーのほうが分かりやすいためです

## プリセット

| プリセット | 吸う / 止める / 吐く | 1ラウンド | 初期ラウンド数 | 所要時間 |
| --- | --- | --- | --- | --- |
| 4-8-8 | 4 / 8 / 8 秒 | 40 秒 | 8 | 5 分 20 秒 |
| 6-12-12 | 6 / 12 / 12 秒 | 60 秒 | 8 | 8 分 00 秒 |
| 4-16-8 | 4 / 16 / 8 秒 | 56 秒 | 8 | 7 分 28 秒 |
| カスタム | 自由 | — | 自由 | — |

ラウンド数は 4 / 6 / 8 / 10 から選べ、「その他」で 1〜20 の任意の値も指定できます。プリセットごとに最終使用値を記憶し、初期値（8）は固定値ではなく出発点です。

## 準備シーケンス

開始ボタンを押してから呼吸が始まるまでの誘導です。スマホを置き、姿勢を整え、目を閉じるための時間を取ります。

| # | ステップ | 秒数 | 目盛り |
| --- | --- | --- | --- |
| 1 | 姿勢を整える | ホーム画面のピッカーで変更（既定 5 秒） | なし |
| 2 | 両鼻で吸う | 3 秒 | 3 分割 |
| 3 | 両鼻で吐く | 6 秒 | 6 分割 |
| 4 | 間 | 1 秒 | なし |

吸う : 吐く = 1 : 2。副交感神経が優位になる比率です。導入呼吸（2〜4）は固定で、ピッカーが変えるのは姿勢ステップのみです。

準備中は両鼻を使うため **左右のバーが同時に動き、∩ 全体が 1 色** になります。本編の片鼻呼吸では片側ずつ動き 3 色を使うため、見た目で取り違えが起きません。

上辺のバーは下端を固定して高さが増減します。吸うと縦バーが減って上辺が満ち、吐くと上辺が減って縦バーが満ちるので、息が腕を上って頭頂に溜まり、そこから戻っていく一つの循環として読めます。

画面をタップすると準備を飛ばして即座に始まります。

## 設定

### 表示設定

| 項目 | 選べるもの |
| --- | --- |
| 言語 | 日本語 / English |
| テーマ | ダーク / ライト |
| 文字の大きさ | 小 / 中 / 大 |
| バーの太さ | 細い / 普通 / 太い |

初回起動時は **2 ステップの設定画面** から始まります。

1. **表示** … 言語・テーマ・文字の大きさ・バーの太さ（言語は端末の設定から推定した値が初期選択）
2. **お知らせのしかた** … 音・ティック・振動・音声ガイド・画面を消さない

どちらもあとから「設定」でいつでも変更できます。

### このアプリを支援する

設定の最下行にあります。押すと短い説明とボタンだけの画面に進み、外部の支援ページ（Buy Me a Coffee）が開きます。

呼吸の導線には一切出しません。完了画面に置けば最も目に入りますが、あの画面は「今日はここで十分」と区切るために主ボタンをあえて「ホームに戻る」にしてあり、そこに金銭の話を差し込むとその設計判断を自分で裏切ることになるためです。

ボタンはティールではなく副ボタン様式にしています。ティールは実質「開始」の色なので、支援をアプリの主目的と同じ視覚的重みにしないためです。

### 最新版を確認

設定にあります。Service Worker がキャッシュを持つ都合で、通常は新しい版が反映されるまで「次に 2 回起動する」必要があります。この項目を押すと、サーバー上の版番号をその場で確認し、新しければキャッシュを破棄して即座に読み直します。

- 最新であれば「最新版です」と表示されるだけで、何も起きません
- オフライン時は確認できない旨を表示します
- 更新時に実施記録や設定が消えることはありません（端末内の保存領域は触りません）

リリースのたびに `index.html` 冒頭の `APP_VERSION` を上げてください。この値が比較に使われます。

### 通知設定

- 音（チャイム）／呼吸音／秒ごとのティック
- バイブレーション
- 音声ガイド（言語に追従）
- 画面を消さない（Wake Lock）／バックグラウンド継続

## 音について

チャイム・呼吸音・終了音は Web Audio で合成しており、音源ファイルを持ちません。音声ガイドのみ合成済みの音声ファイルを同梱しています。いずれもオフラインで鳴ります。

### チャイム

鐘の音が鐘らしく聞こえるのは、倍音が整数倍ではなく **非整数比** で並ぶためです。サイン波 1 本では出ないので、ハム・プライム・三度・五度などの部分音を重ね、高い部分音ほど速く減衰させています。撞木が当たる瞬間の音も短いノイズで加えています。

基音はフェーズごとに変えています。

| フェーズ | 音 | ねらい |
| --- | --- | --- |
| 吸う | C5 | 明るく、吸気を促す |
| 止める | G4 | 控えめ。静止を妨げない |
| 吐く | F4 | 最も低く、収まる感じ |

3 音は互いに協和するため、連続して鳴っても濁りません。

### 呼吸音

息そのものに近い帯域ノイズです。吸うときは中心周波数が上がりながら膨らみ、吐くときは下がりながら減衰します。音階を持たないのでチャイムと喧嘩しません。一時停止して再開した場合は、残り時間に合わせて鳴らし直します。

### 音声ガイド

声は 3 種類から選べます（設定 → 通知設定 → 声の種類）。選び直すとその場で試聴できます。

| 種類 | 内容 |
| --- | --- |
| やわらか（既定） | 高域を抑えた、落ち着いた女性の声 |
| ひろがり | やわらかに薄い残響を加え、奥行きを出した声 |
| 男性 | 低めの、落ち着いた男性の声 |

落ち着いたトーンは音程と速度だけでは作りきれません。合成音声は子音の擦れる高音域が耳に刺さりやすく、それが緊張感の正体になりやすいため、高域を下げて低域を足し、耳あたりを柔らかくしています。

`audio/<種類>/<言語>/` に同梱しており、全 42 ファイル・約 475 KB です。ファイルが読めない環境では自動的に端末の読み上げ機能に切り替わるため、一部が欠けても動作します。

| ファイル名 | 日本語 | English |
| --- | --- | --- |
| `inhale-left` | 左から吸って | Inhale through the left |
| `inhale-right` | 右から吸って | Inhale through the right |
| `hold` | 止めて | Hold |
| `exhale-left` | 左からはいて | Exhale through the left |
| `exhale-right` | 右からはいて | Exhale through the right |
| `prep-inhale` | 両鼻で大きく吸って | Breathe in deeply through both nostrils |
| `prep-exhale` | ゆっくりはいて | Breathe out slowly |

「吐いて」をひらがなで書いているのは、「吐く」に「はく」と「つく」（嘘をつく）の 2 つの読みがあり、合成エンジンが後者を選ぶことがあるためです。ひらがななら読みが一意に定まります。

準備シーケンスの「間」では読み上げません。直後に本編の「左から吸って」が流れるため、重複して聞こえるからです。画面には「左の鼻から始めます」と表示されます。

### アクセシビリティ

キーボードと支援技術で全機能が操作できます。

- 通知トグルは `button role="switch"`、状態は `aria-checked` で伝えます
- プリセット選択は `radiogroup` / `radio`、選択状態は `aria-checked`
- ラウンド数・声の種類・準備時間のチップは `aria-pressed`
- アイコンだけのボタン（← ⚙︎）には言語に追従する `aria-label` を付けています

クリックイベントだけを付けた `div` は使いません。Tab で到達できず、スクリーンリーダーからも操作できないためです。`tools/check.js` がこれを機械的に検査します。

### 整合性の点検

```
node tools/check.js
```

文言・画面遷移・保存データの検証・音声ファイルの実在・Service Worker のキャッシュ対象・アクセシビリティ属性など、別々の場所に書かれていてずれやすいものを突き合わせます。

```
node tools/test.js
```

こちらはロジックの単体テストです。1 ラウンドの構造、フェーズ送り（ラウンド境界、0 秒フェーズの読み飛ばし）、残り秒の表示、時間の表記、保存データの検証を確認します。実装は単一ファイルの IIFE に閉じているため、本体のソースから必要な部分を切り出して Node 上で評価しています。本体を書き換えると切り出しに失敗して落ちるので、気づかずにずれることはありません。

どちらも 1 件でも食い違えば終了コード 1 で落ちるので、変更後はこれを通してから公開してください。

### 音声の作り直し

```
pip install edge-tts
python tools/gen-voice.py            # 全種類
python tools/gen-voice.py warm male  # 指定した種類だけ
```

文言を変えるときは `tools/voice-phrases.json` を編集してから実行してください。生成時だけネットワークが必要です（出力は静的ファイルなので、アプリ実行時に外部通信は発生しません）。ffmpeg が PATH にあることも必要です。

生成後、ffmpeg で前後の無音除去・音量正規化（-18 LUFS）を行い、**44.1 kHz** モノラル 64 kbps の MP3 に変換しています。24 kHz は MPEG-2 拡張にあたり、デコーダによって再生されない端末があるため避けています。先頭に 20 ms の余白を入れているのは、エンコーダ遅延で語頭が欠けるのを防ぐためです。

各音声は対応するフェーズの最短長より短くなければなりません（例：`prep-inhale` は準備の吸気 3 秒以内）。超えると次の案内に切られます。スクリプトは生成後にこれを検証し、収まらないものがあれば失敗します。

実施記録と連続日数は端末内（localStorage）にのみ保存され、外部には送信されません。

## カラー方針

2 テーマで同じ意味づけを保ちます。

| 色 | 意味 |
| --- | --- |
| ティール | 操作できる / 今アクティブ（開始ボタン、選択中、ON のトグル、主ボタン） |
| オレンジ | 継続記録（ストリーク） |
| ニュートラル | 上記以外すべて |
| ティール / バイオレット / オレンジ | 呼吸フェーズ（吸う / 止める / 吐く）。呼吸ビジュアル内部でのみ使用 |

ライトテーマはダークと同じ色相のまま明度だけを落としています。淡い色は白地で沈むためで、文字と背景の組み合わせはすべて WCAG AA（小さい文字 4.5:1）を満たす値を実測で選定しています。

なお完了画面のチェックマークだけは、押せない要素でありながら達成感の演出を優先してティールを使っています。これは意図的な唯一の例外です。

## 動作環境

PWA としての機能（ホーム画面への追加、オフライン起動、画面ロック抑止）は **HTTPS 配信時のみ** 有効です。

## セキュリティとプライバシー

### 設計上の前提

- **外部への通信を行いません。** 通信は「最新版を確認」で自分自身の `index.html` を取得する同一オリジンの `fetch` だけです。外部ドメインへの送信・取得はありません
- 唯一の例外は「このアプリを支援する」のリンクです。**利用者が自分で押したときだけ** 外部ページに移動します。アプリ側から自動で通信することはありません。リンクには `rel="noopener noreferrer"` を付け、遷移先から元ページを操作できないようにしています
- **外部リソースを読み込みません。** CDN・外部フォント・解析タグはなく、依存ライブラリはゼロです
- **`eval` と動的コード生成を使用していません**
- 実施記録・連続日数・設定はすべて端末内の localStorage にのみ保存されます。サーバーに送信されることはありません

### 実装している対策

| 対策 | 内容 |
| --- | --- |
| Content Security Policy | `default-src 'self'` を基点に、外部からの読み込みと外部への送信を遮断。`connect-src` も `'self'` に限定。`object-src` `base-uri` `form-action` は `'none'` |
| 保存データの検証 | localStorage の内容は信頼せず、既知のキーのみを型と範囲を検証して取り込む。未知のキーは取り込まない |
| 出力エスケープ | 文字列を HTML として挿入する箇所はすべてエスケープを通す |
| 権限の最小化 | 要求する権限は画面ロック抑止のみ。位置情報・カメラ・マイク・通知権限は要求しません |

### 既知の制限

クリックジャッキング対策の `frame-ancestors` は HTTP ヘッダでしか機能せず、GitHub Pages ではヘッダを設定できません。代わりに、フレーム内に埋め込まれたらトップへ抜ける（抜けられない場合は中身を表示しない）自衛を入れていますが、これは `sandbox` 属性で無効化できるため完全ではありません。厳密に防ぐ必要が生じた場合は、`_headers` が使えるホスティング（Cloudflare Pages 等）への移行が必要です。

「最新版を確認」はサーバー上の `index.html` から版番号を読んで比較するだけで、内容のハッシュ検証はしていません。HTTPS 前提のため改ざんリスクは低いものの、完全性までは検証していない点は把握しておいてください。

途中で「セッションを終了」した場合、実施記録とストリークには残りません。全ラウンド完走時のみ記録する仕様です。短時間でも記録を残したい要望が出た場合は検討対象になります。
